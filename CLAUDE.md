# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

pnpm monorepo (`pnpm@10.34.5`, Node >=22) for strudel-daw, a DAW-style UI around Strudel. The desktop app is **Phyllo**, a Tauri v2 + React + Vite app. Rust 1.95+ is required for the Tauri side. Every package has `typecheck` (`tsc --noEmit`), `lint` (ESLint) and `test` (Vitest); `pnpm check` runs all three. Dependency versions live in the `catalog:` block of `pnpm-workspace.yaml` (new deps are pinned exact).

## Workspace layout

All source lives under `src/`. `pnpm-workspace.yaml` globs `src/apps/*`, `src/packages/*` and `src/shared/*`; a package must be a direct child of one of those directories to be picked up.

- `src/apps/` — live services (e.g. a Next.js app)
- `src/packages/` — isolated, contextual modules
- `src/shared/` — functionality or logic shared between apps and packages

Place new code by role: anything deployable goes in `apps`, self-contained modules in `packages`, and logic that both apps and packages consume in `shared`. Current packages:

- `src/apps/phyllo` — Tauri v2 desktop app. Frontend: `src/state` (Zustand stores via `createAppStores`), `src/hooks` (the design-system §5 hook contracts — organisms talk to state/engine/native only through these), `src/native` (`NativeApi` with Tauri and in-browser implementations), `src/ui/{organisms,screens,shell,toasts}`, `src/selftest`. Rust in `src-tauri/` (project IO, library index, history, sample folders, MIDI/OSC, export encoders, menu/tray/media keys, sound cache). Organism stories: `pnpm --filter phyllo stories` (port 6007, mock stores).
- `src/apps/manual` (`phyllo-manual`) — the user manual, a VitePress static site (`docs/`) deployed to GitHub Pages by `.github/workflows/manual.yml`. Screenshots in `docs/public/screenshots` are generated by Playwright specs in `capture/` (`pnpm --filter phyllo-manual screenshots`, drives the Phyllo frontend on port 1450); `capture/screenshots.test.ts` fails on missing or unused images. Authoring conventions are in its README; update the affected page and re-capture when UI changes.
- `src/packages/ui` (`@phyllo/ui`) — design tokens (`tokens.css`/`tokens.json`, verbatim copies of `__inspiration/mockups/design-system`), `ThemeProvider`, bundled fonts, atoms and molecules, Storybook stories. Must not depend on `@phyllo/engine` or Tauri. Organisms, screens and stores live in the app.
- `src/shared/model` (`@phyllo/model`) — `types.ts` (shared types; orchestrator-owned), reducer, factories, param specs, serialization, time helpers, `content/` (starters, tips, catalogs).
- `src/packages/engine` (`@phyllo/engine`) — codegen (model → Strudel), parse (code → model), mini-notation ↔ step grid, share links, and the Strudel runtime (`createEngine`). Strudel ships no types: ambient declarations live in `src/types/*.d.ts` and must stay referenced from `src/index.ts`. Verified Strudel behaviour is in `docs/strudel-verification/REPORT.md`; Vitest inlines Strudel deps. Browser tests: `pnpm --filter @phyllo/engine e2e`.

## Commands

Root scripts fan out across every workspace package with `pnpm -r`, so they only do work once a package defines the matching script:

```bash
pnpm install
pnpm build            # pnpm -r build
pnpm dev              # pnpm -r --parallel dev
pnpm typecheck        # pnpm -r typecheck
pnpm lint             # pnpm -r lint (ESLint flat config at the repo root)
pnpm test             # pnpm -r test (Vitest)
pnpm check            # typecheck + lint + test (what CI runs)
pnpm e2e              # Playwright user flows against the Vite dev server (port 1420); `pnpm --filter phyllo e2e:visual` for screen captures
pnpm stories          # Storybook for @phyllo/ui on port 6006
pnpm --filter <name> <script>   # target a single package, e.g. run one package's tests
```

Run the desktop app with `pnpm --filter phyllo tauri dev` (not root `pnpm dev`, which only starts the Vite frontend in a browser, where the in-memory `NativeApi` is used). `pnpm --filter phyllo selftest` builds a release `.app` and runs the definition-of-done flow inside WKWebView (temp `PHYLLO_HOME`). Plan, progress and decisions: `PLAN.md`, `PROGRESS.md`, `DECISIONS.md`.
